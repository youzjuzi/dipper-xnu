## 当前阻塞与限制

- 完整 XNU `all` 的导出检查和工具生成仍失败；尚无全新 Ubuntu 安装验证。
- 通用设备配置和充电全过程未验收；用户状态持久保存只完成首测（见上表），异常退出会丢上次保存之后的改动。
- 桌面卡顿、功耗及 GPU SMMU/基带退出恢复仍需处理；各轮之间要求完整重启，不能直接连续 rerun。
- 电话、移动数据、完整音频（含蓝牙音频）、摄像头、定位及其他未覆盖硬件不列为可用。
- GPU 初始化表与 APSL 内核组合的分发条件仍未解决，见 [GPU 许可说明](legal/GPU_LICENSE.md)。

## 温控、渲染与性能诊断

补丁纳入可选的温控主动降档、帧剖析与调度采样，以及渲染导入和静止图像检查优化。`ffix` 缺省 1；通道重排共享导入（bit2）和渲染目标初始 GPU 拷贝（bit3）默认关闭。非 dipper 目标的温控和采样仍需显式启用；dipper 的温控默认目标现为 66 °C，采样仍须显式启用。默认路径仍存在条件判断，不能称为零开销。

`rwtouch` 提供可重复输入的 `mark` 时间标记及 `mem` 测量步骤，`mem` 未经设备验证。此次验收为干净重放和主机构建，未新增设备结论；参数默认值与证据见 [验证记录](validation/VALIDATION.md#性能源码导出与主机重建2026-11-05)。

## dipper 启动参数默认值

27 项固定配置集中为 dipper 默认值，显式参数（含 0）覆盖；其他平台保持原行为。保留 loader 核心选择、存储选择和私有身份参数，用户态从 `kern.bootargs` 获得相同有效配置。配置与覆盖方法见[启动教程](install/STARTUP.md#dipper-短启动参数与默认值)。旧完整参数与新 bench 的主机解析逐项一致，干净内核 build 和载荷校验通过；daily 载荷已在设备上进入桌面，`kern.bootargs` 展开值与旧完整配置一致，未改变既有设备功能结论。

## 降低渲染分辨率（可选）

显式追加 `fbscale=2 fb_dpu=1` 后，系统按 750×1624 渲染，由显示硬件 DPU 放大到面板，处理器只做整块拷贝；SpringBoard 库把 UIKit 的状态栏后备样式换成 iPhone X 的样式，红色占位条消失。设备上已进入桌面，状态栏显示正常，持有人感到明显更流畅；每帧拷贝耗时中位数由处理器放大的 6.5 ms 降到 0.5 ms。**实时壁纸不绘制**（系统查不到 750×1624 @2x 的屏幕类别，壁纸进程什么都不画，窗口是黑底），改由 SpringBoard 库在最上面盖一张静态图（`/redwood/etc/wallpaper.jpg`，没有则用渐变）；设置里换壁纸不会改变它。画面比原来软。设置、信息等应用在降分辨率的启动里出现过闪退；原分辨率下各打开一次没有闪退（样本小），原因未定。默认不启用；Wi-Fi、触摸、按键在该配置下的完整回归和长时间稳定性未验证。参数、前提和限制见[启动教程](install/STARTUP.md#降低渲染分辨率可选不是默认值)，数据见[验证记录](validation/VALIDATION.md#降低渲染分辨率与状态栏2026-11-10)。
